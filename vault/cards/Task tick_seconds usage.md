Follow-up to the live task queue inspector: `queued_tasks()` has no real per-task tick/seconds usage field - the relevant slots (`ToastStunt/src/tasks.cc`) are dead placeholders from an old clock-based scheduler, and no other builtin reports a task's cumulative consumption (`ticks_left()`/`seconds_left()` only cover the *current* task's own remaining budget). Getting real usage would need a new C-side patch tracking cumulative ticks/seconds per task in the task struct - same category of change as the existing `handle_verb_programmed` patch (M2's capture hook). Not attempted as part of the inspector itself; tracked here so it isn't lost.
